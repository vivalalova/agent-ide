# Markdown 寫作規範

文檔的預設是「不提就不會做」— 會出現「要做 X」就表示這是非預設動作。

- 刪「要做 X」時直接拿掉，不必替成「禁 X」— 拿掉後預設自動回到「不做」，禁令多餘；解禁同理：刪禁令即可、不加「可做 X」，與既有預設（含 agent/工具自帶描述）一致的授權條是廢字
- 文件陳述最終狀態，歷史歸 git log — 禁 changelog／輪次紀錄段／「下列新版與舊版不同」加法對照段（「已修」「round-N」「初稿規劃→未採用」「原本…現在…」皆 log 訊號）；驗證出處戳記（版號、日期、裸「實測/實證」標籤）同屬 log 訊號，佐證細節（錯誤訊息、欄位名、來源連結）與未驗證警示是現況資訊照留；行為融入持有該機制的章節修正原文，不修的風險寫成「已知限制」現況條目
- 簡潔、條列、說人話：一句塞多個括號補充＝拆句訊號；≥3 個獨立子項（映射分支、並列守則）擠同一行＝子項條列訊號，子項皆短詞、單行掃得動則留行內
- 禁元敘述／自我指涉 — 談本檔自己做不做什麼、規則在哪、重不重述（「本 command 不重複定義」「定義不在此重述」「本 skill 只負責 X」）對讀者零影響：規則直接寫、引用直接指路，別宣告「我不重複」。自檢：一句不要求讀者做任何事、只自陳或解釋設計動機 → 刪；已知限制與消歧義屬現況資訊要留
- skill／command 等程序型文件的強制要求（必做動作、必交付產出、互動 gate）要落在執行流程的編號步驟或收尾 gate，別只埋在敘述段 — 否則跑流程時會被跳過；有前置依賴、需先有上一步結果才能做的，放對應後置步驟
- 專案／plugin scope 的 .md（隨 repo 散佈）禁引用 user scope（`~/.claude/`）內容 — 他人 clone 後該檔不存在即失效；要引用的對象須一起進同個 repo
